## Acceptance

- Sources are the donor&#x27;s stage0.c mount call and the NAT-077 probe&#x27;s read/print scaffolding, pinned, each deviation listed; the SHA-256 code uses the ARMv8 crypto instructions and is checked against FIPS vectors and against hashlib on random buffers in Unicorn (the instructions are supported or modelled by an independent reference, stated); a plain-C fallback is kept for comparison only.
- The host produces, with apfs_lib from the same padded image, the list of paths with sizes and SHA-256 that the probe must print (expected.json), and a comparator that turns the probe&#x27;s console text into pass/fail per path; refusal classes are separate for: mount failed (errno), path missing, size differs, digest differs, timeout.
- The probe is built with the project toolchain as a static ad-hoc-signed Mach-O and checked by the independent reader (no dynamic dependency); the time budget (read rate 33 MB/s measured on the S24 in NAT-078, hash rate by instruction) shows the chosen file set fits 55 s; the statement of what the host test does not show (the kernel&#x27;s apfs VFS is untested on the phone) is in the README.
