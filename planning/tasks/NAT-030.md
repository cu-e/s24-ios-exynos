## Acceptance

- An interpreter that executes the real payload bytes (decoded with capstone, executed by independent code) runs the kernel&#x27;s start_first_cpu from the entry with the loader&#x27;s real boot_args layout and the measured window (physBase 0x9de400000, kernel virt base 0xfffffff004000000) and reaches, in order, the five assembly checkpoints when the XNULDRST slot holds stub PA, checkpoint N and PA-VA; each stop presents x0=0, x1=0, x2=2, x3=N and a cleared SCTLR_EL1.M.
- With the slot left at zero the same run falls through all five sites, builds the bootstrap tables, enables the MMU (SCTLR_EL1 write) and returns through its own `ret` to the virtual address of arm_init; every instruction fetch and data access after the MMU write is translated by a table walker that reads the tables the kernel itself wrote (TTBR0 V=P and TTBR1 KVA), and the translation of the kernel&#x27;s own PCs and of arm_init matches window base + (VA - virt base). A deliberately wrong boot_args (wrong physBase or virtBase) is detected by the same checks, so they can fail.
- The run states what the interpreter does not model (caches, the full ISA, timing, system-register side effects beyond the listed ones) and labels every result host-test/simulation, not hardware evidence. Nothing is run on the phone.

## Steps

1. Decode the start code range and list the instruction forms it uses
2. Write the interpreter and the table walker, run the real bytes
3. Add negative controls and document the model limits
