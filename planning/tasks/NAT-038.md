## Acceptance

- An inventory of every existing USB/DWC3/Exynos-PHY code base reachable from this repository (pinned vendor kernel s24-linux and s24-bsp-reference: dwc3 core and Exynos wrappers, eUSB2/USBDP PHY drivers and repeaters; the upstream s24-port sweet DWC3 patches 0072-0077/0081; the USB-001 read-only block adapter and its S24 source profile; the NAT-016 host archive; S-Boot Download Mode) with pin, licence, what is reusable as is, as a port, as a reference or not at all, and why; nothing is copied without attribution.
- A comparison of candidate channels (EP0 control-pull gadget, bulk-IN push gadget, CDC-ACM, ECM/UDP as in the sweet patches, S-Boot USB reuse, RAM retention read from Android, UFS write into the RECOVERY tail, UART) against: independent of a return to the bootloader, what must be brought up, risk to Android and data, number of unknowns, code size. A channel that needs the phone to return to S-Boot/Android before the host can read anything is recorded as retention, not as the log channel.
- The chosen minimal channel with its wire format for text and for an exception frame, the host collector design (reuse of NAT-016 archive.py), the verification criterion (the host, unattended, receives and stores a message from a real native run with a boot ID that cannot come from a previous run) and the child tasks that resolve each remaining unknown, created with dependencies.
