## Acceptance

- The kernel entry point, its displaced first instruction and the NOP padding that can host a stub are derived from the real payload header and segment table (not from the loader&#x27;s own log), and the stub placement (entry word plus NOPs, 8-byte aligned literals) is checked against the segment&#x27;s copied file range.
- A hash-anchored, deterministic source variant (loader-diag-xnu-entry) installs a position-independent stub at the kernel copy&#x27;s entry before the full-window cache clean and returns the entry to start.S; the stub sets a known stack and calls a noreturn marker routine that draws STAGE 0x50 (XNU_ENTRY) plus the stub PC, the incoming x0, the current EL and SCTLR M/C/I bits and holds. No instruction of the XNU kernel itself is executed by this variant: the stub overwrites the first words of the entry, and the original first word is not replayed. Every earlier image stays byte-identical (new code is behind new macros).
- Host checks that are independent of the implementation: the assembled stub bytes are decoded by capstone and each instruction, literal address and register use is asserted; the real installer function (compiled for the host) is run on a copy of the real kernel segment bytes and only the intended words change; the marker&#x27;s frames decode with decode.py/decode_video.py (new kind) and the XNU_ENTRY stage can only be produced by the stub path; the alignment scan and trap checks pass. All labelled host-test: nothing here shows that the S24 reaches the kernel copy.
- A RECOVERY package is built and host-tested, a session driver is gated on a new decision file, and an image-specific decision request (SHA-256s, device access, what runs and what does not, risks, recovery) is put to the owner. Nothing is flashed or run on the phone and no jump is made before that decision.
