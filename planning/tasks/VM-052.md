## Acceptance

- A static NDK VMM (no external libraries) lays out RAM, Image, initrd and an FDT the way crosvm does for avfboot, with an in-kernel vGICv3, PSCI, an ns16550a console at 0x3f8 and a PL031 RTC; host unit tests cover the FDT writer and device models.
- On the S24 as root from tmpfs, under decision 0002: avfboot (built from the pinned scion-avf source) prints its banner on the VMM console, and the run ends by PSCI or by the VMM&#x27;s own bounded timeout, with the VMM process gone afterwards.
- Record console output, exit cause, uptime before/after and the removal of the RAM directory. Do not claim an XNU boot unless the console shows one.

## Steps

1. Write the VMM, FDT writer and device models with host tests.
2. Build avfboot from the pinned source.
3. Run on the S24 with a bounded timeout and record the console.
