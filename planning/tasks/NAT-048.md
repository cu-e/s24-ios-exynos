## Acceptance

- docs/procedures/nat-048/session_reset_canary.py follows the NAT-037 driver (preflight read-only by default, --execute one RECOVERY write with full-hash readback and one `adb reboot recovery`, --restore stock without reboot) but is pinned to the NAT-044 package-001 hashes for the selected image (loader-diag-reset or loader-diag-reset-bl), refuses every adb call unless the agent-written decision file for that image exists, and uses its own one-shot marker per image. It differs from the NAT-037 driver only in the pinned names, the image selection and the watcher start (a host test diffs the two).
- docs/procedures/nat-048/usb_watch.py records every USB device appearance/disappearance (VID:PID, iProduct/iManufacturer from sysfs strings, bus path, CLOCK_MONOTONIC and UTC timestamps, poll interval) as fsynced JSONL from before the reboot until a stop time; it reads sysfs only and never opens a USB device or sends a request; the driver starts it before `adb reboot recovery` and records its path and start time in report.json.
- docs/procedures/nat-048/analyze_reset.py reads the watcher log, the driver report (reboot request time) and the NAT-044 build record and states for U1+U2 (a re-enumeration at the deadline, before the watchdog time) and U3/U4 (enumerates as Download Mode, iProduct SAMSUNG USB, without an owner action) one of supported / refuted / undetermined with the timestamps used, never inferring from missing data (no log = undetermined); the baseline of runs 001-009 (SEC_UPLOAD about +95 s after the reboot request) is a stated constant with its source.
- Host tests with a fake adb and a fake sysfs tree cover the open-gate flow, the closed gate (no adb call), a readback mismatch (stock restored, no reboot), the one-shot marker, the watcher&#x27;s event stream (appear, disappear, re-enumerate, strings) and the analyzer&#x27;s verdicts on synthetic logs for every outcome including no log; a mutation check on the driver and analyzer. Nothing talks to a phone.
