## Acceptance

- A freestanding C engine (no interrupts, no allocation, one event ring, one TRB per control stage) that enumerates as a vendor-specific full device (pid.codes test VID/PID, no class), answers GET_DESCRIPTOR/SET_CONFIGURATION and vendor control-IN requests that read a RAM log ring by offset and a fixed exception frame, plus a reserved boot-ID field; DWC3 register and TRB layouts follow the pinned vendor core and databook usage in Linux, with attribution (GPL-2.0, per-file licence kept).
- A host model of the DWC3 device side (register file, event buffer, TRB processing for control transfers) and a USB host stub drive the engine in host tests: descriptor reads, partial reads, ring wrap/overrun markers, an exception frame, requests arriving while the engine is in its hold loop, malformed SETUP packets; mutation checks show the tests fail on seeded defects.
- tools/s24_logd.py (or equivalent under docs/procedures/nat-041) waits unattended for the device, pulls the ring with libusb control transfers, converts it to NAT-016 JSON frames, writes them through archive.py with a host nonce that makes the boot ID unique, and survives device disappearance; tested against a fake libusb layer and the model. No phone is touched.
