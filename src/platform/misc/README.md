# E1S miscellaneous peripheral requirements

Status: source-backed interface specification only. No native driver, Apple framework adapter, firmware, security credential or hardware result is supplied here. `check_sources.py` verifies the provenance of the claims against real pinned Git blobs; it does not emulate a peripheral. All five native acceptance gates below remain open.

Target: measured SM-S921B/e1s, s5e9945, Android15 firmware S921BXXS9BYH3, Linux6.1.93. The [sanitized local profile](../../../research/notes/DEV-001-profile.md) establishes that identity, not operation of these five peripherals. Reviewed `s24-linux` is **417484173abc2c4fa93e738ea82ad9f2e84911b1**. The older hardware-map BSP reference is **f85e53cfa5497ead5d78821efbac84e51f37a4e1** (S921BXXS8BYG2). Neither pin is established as the exact running BYH3 source/config/DTBO. A source address is a candidate, not authorization to map or probe it.

The [source index](sources.md) links exact files, hashes and reviewed line anchors. `sources.json` records22 files and81 anchors. Six files differ between pins, including codec and DP code/config. The16 identical reviewed files do not establish the identity of the complete BSP. GNU/Linux/vendor source retains its original per-file GPL and other notices; this work copies no driver implementation into XNU. Code reuse requires a separate license/architecture decision.

## Shared boundary requirements

Every future request must carry a version, caller/session identity, request ID and absolute monotonic deadline in nanoseconds; completion returns the same ID, terminal result and completed extent/count. Cancellation, timeout, reset and shutdown must terminate ownership exactly once. These are new design requirements, not a measured Samsung or Apple ABI. The selected XNU frontend and wire layout remain unimplemented and require an independently versioned ABI review.

A board input bundle must identify exact model, hardware revision, firmware build, final DT/overlay selection and effective config; list byte ranges, IRQ domain and trigger, pin states/polarities, clocks, regulators, power domains, DMA/IOMMU aperture/coherency and ownership; and hash each permitted firmware/config input with provenance/license and size. Unresolved fields are unavailable, never zero-filled defaults. A provider may announce a capability only after its matching native acceptance passes. Source checks, Android inventory and host models must never set that status.

Each frontend must reject unsupported modes before any side effect, retain no stale handles across generation/reset, and return explicit unavailable/unsupported/timeout/cancelled/hardware-fault status rather than success with empty output. Runtime bounds must come from reviewed hardware documentation and configured policy; no max drive current, reset delay or secure command is inferred from a donor. Exact Apple iOS16.5 user-client selectors, serialization, entitlements and service semantics are missing for every boundary below.

## Haptics

**Established source mapping.** The E1S generated overlay selects I2C controller `hsi2c_4`,7-bit address0x40 at1MHz, CS40L26A, IRQ gpa3-7 and reset gpp2-2. Board tuning selects deferred firmware loading, OWT compatibility1.0.0 and three `svc-le` actuator bins. The selected config enables `CONFIG_INPUT_CS40L26_I2C=m`, Samsung features and SEC input-FF; the vendor driver implements FF_PERIODIC with FF_CUSTOM/FF_SINE, upload, playback, gain and erase. See [board overlay](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/samsung/e1s/e1s_eur_openx_w01_r13.dts#L2402), [tuning](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/samsung/cs40l26.dtsi), and [driver](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/vibrator/cs/cs40l26/cs40l26.c#L3821).

**Exact required inputs.** Obtain final controller/pin/IRQ routing and voltage/reset timing; supported firmware revision, DSP mailbox/register ABI; actuator part/calibration, resonance and safe amplitude/duty/temperature limits; effect-table indices and waveform formats. Source names `cs40l26.wmfw`, `cs40l26-calib.wmfw`, `cs40l26.bin`, `cs40l26-wt{index}.bin`, `cs40l26-svc{index}.bin` are identifiers, not supplied files or grants to redistribute. The1/2/3 bin mapping must be selected by real actuator calibration, not guessed. Source policy has high-temperature reference48 and gain ratio70; units, applicability and safety must be confirmed before adopting them. VA/VP supply placeholders are disabled in the generic tuning file; physical supply control remains unresolved.

**Required interface.** `describe` returns permitted waveform kinds/IDs, amplitude scale, timing quantum, effect slots and calibrated bounds. `upload` takes immutable bytes, exact format/version/length and digest and returns a session-scoped effect handle. `play` takes that handle, gain in the declared scale, repeat count, start time and duration in nanoseconds. `stop`/`erase` are idempotent and acknowledge hardware idle/resource release; upload/play failures cannot leave an actuator energized. Arbitrary FF_CUSTOM bytes are unavailable until their vendor format and length limits are documented. Pattern scheduling must distinguish requested duration from observed physical motion. No Core Haptics/Taptic Engine equivalence is asserted.

**Separate native acceptance HAPTICS-NATIVE.** After transport/power and safety inputs are reviewed, verify chip/firmware identity, calibration-bin selection and a bounded manufacturer-approved effect with an independent vibration measurement; exercise repeated play/stop, cancel, reset, thermal clamp and missing firmware. Record requested versus measured timing/amplitude, deadline and measured idle after Stop, with declared acceptance limits chosen before execution. Prove failures remove drive and release slots/power. A host FF object or Android haptic animation cannot pass this gate.

## NFC

**Established source mapping.** E1S overlay selects `hsi2c_39`,400kHz,7-bit address0x27, `sec-nfc`/SEN6; VEN is PMIC s2mps28_2 GPIO4, FIRM gpf1-1, IRQ gpa2-3, clock request gpa4-0, cold reset gpf1-0 and `nfc_pvdd` l12. The selected defconfig enables `CONFIG_SAMSUNG_NFC=m` and `CONFIG_SEC_MX_NFC=y`; [LSI Makefile](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/nfc/lsi/Makefile) selects `nfc_slsi_sec` with `sec_nfc.o`, not the similarly named `drivers/nfc/samsung` variant. This is a source/config mapping, not verification of the loaded BYH3 module. See [overlay](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/samsung/e1s/e1s_eur_openx_w01_r13.dts#L4400).

**Exact required inputs.** Final rail/reset/clock sequence and allowed ownership among NFC/eSE users; SEN6 firmware/NCI version, initialization/configuration and RF tuning; exact IRQ/read framing and power-state timing; selected vendor HAL/native protocol and legal firmware provenance. Source exposes a512-byte allocation and260-byte message limit; neither establishes the maximum NCI logical message or complete packet/reassembly semantics. eSE command vocabulary, credentials and payment integration remain separate unavailable inputs.

**Required interface.** A single bounded session owns the controller; `describe` returns transport/message limits and supported read-only discovery modes. `receive` supplies capacity and deadline, returns exact bytes and complete/partial-packet status; `transmit` requires explicit allowed-mode policy, immutable bytes and exact length. `set_mode`, `sleep`, `wakeup` and shutdown require a serialized state machine with cancellation and rollback. The [LSI header](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/nfc/lsi/sec_nfc.h) uses ioctl magic'S', SET_MODE1, SLEEP2, WAKEUP3, SET_NPT_MODE4, conditional COLD_RESET5; the [implementation](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/nfc/lsi/sec_nfc.c#L937) treats `arg` as an integer despite `_IOW`. GET_MODE0 is declared but absent from that switch; the Samsung variant's SHUTDOWN6 must not be silently imported. Port command semantics explicitly instead of copying Linux ioctl numbers/argument assumptions to XNU. Firmware download, eSE cold reset, card emulation and payment are disabled pending their own requirements and authorization. Core NFC, Wallet and Apple Pay compatibility is unestablished.

**Separate native acceptance NFC-NATIVE.** Under a separately authorized RF/device task, identify controller/firmware, use an owner-approved nonpayment test tag, and verify bounded discovery/read with known public test bytes and independent controller responses. Exercise IRQ loss, short/oversized frames, unplug/power failure, cancellation, Stop and exclusive ownership without eSE/payment transactions or firmware mode. Tag IDs and captures stay private/sanitized. No live NFC action occurred for MISC-001.

## Biometrics

**Established source mapping.** Board data names QFS4008, IPC gpa0-6, WUHB gpa0-1, VDD_BTP_1P8/l13 and a3.0V supply name whose generic regulator stanza is disabled. Secure production clock names select PERIC2/USI11. The ordinary SPI11 node at33,333,333Hz is **factory gated**. `CONFIG_FINGERPRINT_SECURE=y` plus nonfactory enables `ENABLE_SENSORS_FPRINT_SECURE`. A normal SPI device is therefore not a production authentication path. See [board](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/samsung/fingerprint_qfs4008.dtsi), [secure gate](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/fingerprint/fingerprint.h#L25) and [control definitions](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/fingerprint/qfs4008_common.h).

**Exact required inputs.** Final rails/clock/pin/power sequence; trusted-world ownership, matching trusted application and secure transport ABI; firmware/calibration format and legal inputs; secure enrollment/match/token semantics, key hierarchy, isolation, antirollback, rate limiting, lockout, deletion and reset policy. These are absent from the reviewed public control surface. No keys, identity templates, raw fingerprint images or personal enrollment artifacts may enter Git or shared reports. A sensor chip name, IRQ or permissive factory driver does not establish these inputs.

**Required interface.** Split nonsecurity diagnostics from any authenticator. The source creates `qbt2000_fd` and `qbt2000_ipc`, FIFO128 events, FD down/up values1/2 and CBGE_REQUIRED3, with controls21–32/38/39/105 for power/clock/IRQ/etc. These control numbers are not matching or identity results. The source read copies an enum and returns the `copy_to_user` residual (zero on successful copy), so an adapter must specify/test its own byte-count semantics; do not treat the copied control code as a portable stream ABI. A diagnostic event carries channel, generation, event kind, monotonic timestamp and explicit overflow/loss; no identity or authentication boolean. An authenticator must remain unavailable until a reviewed secure protocol supplies challenge binding, opaque token format, expiry, caller authorization and verified error/lockout semantics. A normal-world callback must never mint a trusted authentication result.

**Separate native acceptance BIO-NATIVE.** First qualify only authorized, manufacturer-supported nonpersonal diagnostics: power/clock transitions, bounded IPC/WUHB event handling, cancellation, overflow and idle after shutdown, with no secure-store changes or raw captures. A later, separately scoped secure-authentication gate requires proof of isolation, token verification, challenge/replay rejection, lockout, enrollment/deletion/reset behavior and private owner-approved fixtures; diagnostic success cannot pass it. Samsung biometric control does not implement Apple SEP, Touch ID/Face ID, LocalAuthentication or Keychain security guarantees. No spoofed identity service is supplied.

## Video codecs

**Established source mapping.** Exynos MFC is the video codec boundary, distinct from camera capture and GPU display. [MFC DTS](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/exynos/s5e9945-mfc.dtsi) declares MFC/MFD register pairs0x1e0d0000/0x1e0c0000 and0x1f0d0000/0x1f0c0000 (each0x10000), IRQ symbols INTREQ__MFC/INTREQ__MFD, SYSMMU domains,36-bit DMA and `mfc_fw_rmem`. Normal firmware IOVA slots are0x10000000/0x10100000,1MiB each; secure slots0x10200000/0x10300000 are distinct. Those are source IOVA reservations, not recovered physical RAM. The source uses V4L2 separate decoder/encoder operations, [firmware name](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/media/platform/exynos/mfc/base/mfc_common.h#L110) `mfc_fw.bin` and [imgloader/S2MPU verification hooks](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/media/platform/exynos/mfc/mfc_core_ops.c#L1258).

**Exact required inputs.** Match final DT/reserved physical memory, interrupt routing, clocks/reset/power/QoS, cache/LLC behavior, SYSMMU mappings and fault teardown; obtain permitted firmware digest/version and mailbox/command/register ABI including verification. Pin supported codec/profile/level, bit depth/chroma, output layout/modifier, stride/plane alignment, buffer count, maximum dimensions/bitrate, colorimetry and timestamp/reorder rules. DTS stride256, P010 and SBWC flags are source options, not proof of usable formats. Existing source H264/HEVC/VP8/VP9/AV1 mode tables do not qualify throughput or every format. Protected decode and secure mappings are unavailable until their separate security dependencies are reviewed.

**Required interface.** `query` returns only qualified codec/profile/format combinations. `create` takes encode/decode direction, codec/extradata bytes+length, dimensions, color metadata, negotiated planes and declared limits. Buffer registration takes object identity/generation, byte extent, per-plane offset/stride/rows, access rights and DMA mapping authority; never trust a caller-supplied physical address. `submit` takes exact used length, presentation/decode timestamps, flags, acquire fence and deadline. Completion returns consumed extent, actual output planes/timestamps, format-change/EOS or explicit error and a release fence. Buffers stay owned until DMA has stopped, IRQs/fences drained and IOMMU invalidation acknowledged; failure must not free in-flight mappings. Drain, flush, resolution change and cancel have explicit terminal behavior. VideoToolbox/CoreMedia/IOSurface ABI, FairPlay and protected playback are unqualified.

**Separate native acceptance VIDEO-NATIVE.** Start with one declared unprotected codec/profile/resolution using an owned/public licensed deterministic stream and independent software decoder/reference frames. Check plane extents, color, frame count/order/timestamps, output checksums or declared lossy error bound, and bounded completion. Then qualify encode separately by independent decode; measure dropped frames/latency/thermal behavior against predeclared requirements. Include malformed/truncated streams, allocation/firmware failure, seek/flush/EOS, resolution change, cancellation and IOMMU fault cleanup. Record each codec/profile separately. A rendered GUI or software decoder result cannot qualify MFC.

## External display

**Established source mapping.** The nondual DPU path is selected in the reviewed defconfig. [DP DTS](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/exynos/s5e9945-drm-dpu.dtsi#L803) names DP link0x17880000 size0x5da8, USB-DP PHY control0x178d0000 size0x250, TCA control0x178e0000 size0xfc, INTREQ__DP_LINK, pd_hsi0 and two clocks. [Board extension](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/arch/arm64/boot/dts/samsung/e1s/s5e9945-e1s_common.dtsi#L1263) enables `drmdp`, AUX output-enable PMIC1 GPIO1, SBU select PMIC1 GPIO2 and USB orientation select gpc7-1, but explicitly marks PMIC GPIOs for later modification. Treat that warning as an unresolved board input. [DP implementation](https://github.com/dx4m/android-kernel-samsung-e1s/blob/417484173abc2c4fa93e738ea82ad9f2e84911b1/drivers/gpu/drm/samsung/dpu/displayport/exynos_drm_dp.c) consumes PDIC connect/link-configuration/HPD events, performs link training and publishes EDID modes. Internal DSI scanout does not prove the DP chain.

**Exact required inputs.** Coordinate with USB-001 for actual MAX77775/Type-C/PD ownership, negotiated alternate mode, lane/pin assignment and orientation. Obtain effective board GPIOs, PHY calibration/clock/power sequence, AUX/DPCD/HPD timing and IRQ semantics, DPU/DECON routing, DMA/fence ownership, bandwidth limits and sink/cable/link capability. EDID bytes require extent/checksum/extension validation and private serial filtering. HDCP keys/secure transport and protected output are unavailable; no key extraction or protection bypass is proposed.

**Required interface.** A connector generation owns attach/detach/orientation/PD state; distinguish cable attached, alternate mode entered, HPD asserted, link trained and stream active. `enumerate` returns validated sink modes and available bandwidth, never a hardcoded desktop size. `modeset` takes a negotiated mode (pixel clock Hz, totals/sync polarities, color encoding/depth), lane configuration and deadline. `present` takes qualified image/plane/modifier descriptors and acquire fence; completion requires real vblank/flip acknowledgement and returns a release fence. Detach invalidates old modes and requests, stops DMA/link safely and restores shared PHY ownership to USB; late HPD/completions from old generations are rejected. DP audio is a separate audio acceptance, and no HDMI adapter, AirPlay, HDCP, UIKit second-screen or Apple display-service compatibility follows from unprotected DP pixels.

**Separate native acceptance DP-NATIVE.** With a separately authorized connector task, use an identified owned sink/cable and public test pattern. Record PD alternate-mode/orientation/lane results, validated EDID/DPCD, measured trained link and independent sink image at one explicitly declared mode; compare scanout checksum/physical image and vblank timing against the submitted pattern. Exercise both plug orientations, disconnect during queued present, retraining, unsupported modes and failed AUX/HPD/PD; prove no stale DMA and restoration of USB ownership. Qualify modes and audio separately. Android DeX advertising and source `status=okay` cannot pass this gate.

## Reproduce source verification

```sh
python3 src/platform/misc/check_sources.py \
  --repo /home/egor/dev/pet/s24-ios-exynos/references/s24-linux \
  --comparison-repo /home/egor/dev/pet/s24-ios-exynos/references/s24-bsp-reference \
  --negative-controls
```

The checker disables Git lazy fetching and optional locks; it verifies exact commit objects,22 blob digests,81 source anchors, comparison classification and seven rejection controls. It opens no device node and executes no upstream code. Missing local objects fail with an explicit unavailable result; populate only a separate local reference under a new registered fetch procedure. This check is a provenance boundary, not an ABI parser, DTS preprocessor, build, firmware validation or native test. Unknown effective DT/config/runtime inputs remain unknown even if every source assertion passes.
