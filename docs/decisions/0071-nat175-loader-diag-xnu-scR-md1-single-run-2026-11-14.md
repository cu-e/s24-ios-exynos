## Rationale and new verifiable reason

NAT-173 (C2) moved cpu0 from 960 to 1958.4 MHz and cut the driver time from 17.9 to 8.9 ms. The idle home screen stayed at
~9.6 fps because userland hands over a frame only every ~105 ms (NAT-164), so that run could not measure capacity. NAT-174 adds the
missing variable, an animation: kernel-generated page swipes through the same touch post path that NAT-144's real taps used. The
command line swaps `cpuload=1000` for `touch_lat=1`, so swaps are timestamped. This is a new measurement, not a repeat.

## What changes against NAT-173's image

- `bsd/e1s_touch.o` adds `e1s_swipe_thread`. From 215 s to 375 s of uptime, every 3 s, it posts finger 9 at mid-height: a DOWN at
  0.8 (or 0.2) of the width, 12 MOVEs 16 ms apart, then an UP; the direction alternates. Only touch-sample posts to userland. No
  register is written that NAT-170/173 did not already write.
- `touch_lat=1` instead of `cpuload=1000`. The same stock FREQ_REQ {2, 1959000, 0, 0} on APM channel 0 as decision 0070 is sent
  again by default (sources tabled there).

## Risk, time limit, stop mechanism, restore

Same bounds as decisions 0063–0070: delivery cap 225 s, receive cap 240 s; timed return 270 s with the fed watchdog; loader
deadline 595 s → Download Mode; watcher and collector 720 s.

Specific risks:
- **Synthetic touches open something unexpected.** They are page swipes at mid-height. Any app they open lives in the RAM-only
  iOS and is gone at the return.
- **More log lines.** The log is a fixed tail, so lines are lost rather than causing a stall.
- **The clock and heat.** As in decision 0070: the stock level, the firmware's own voltage table, ≤ 270 s.

If the phone loops through SEC_UPLOAD (NAT-146):
1. the host does not deliver again;
2. the owner forces a restart (Volume Down + Side, 7–10 s), then holds Volume Up + Volume Down and presses Volume Up for Download
   Mode;
3. the stock restore follows.

No partition other than RECOVERY is written. Restore: nat-012 `restore_stock.py` with the venv python; `check_android.py` and
nat-013 assess; `task done` or `task update` BEFORE the permission is closed. One attempt, no retry without a new verifiable reason.

## Physical action asked of the owner

None, unless the SEC_UPLOAD loop above happens. Please do not touch the screen: the swipes are generated by the kernel.
