# DES / TDES component qualification (KRN-032)

This is an owned host/ARM component bridge, not a crypto provider. It supports the selected public ECB/CBC callbacks, not Apple's private ABI, arbitrary general mode consumers, FIPS validation or side-channel resistance. DES/TDES are legacy algorithms, unsuitable for new security designs. A full kernel or phone has not executed this component.

## Source and actual selected demand

Selected XNU is `c54f35ca767986246321eb901baf8f5ff7923f6a` in the main checkout's read-only `references/apple-xnu`. We consume its genuine `EXTERNAL_HEADERS/corecrypto/ccmode_impl.h` declarations rather than copying headers or implementations. `libkern/libkern/crypto/des.h` provides 256-byte DES and 768-byte TDES ECB schedule slots. `libkern/crypto/corecrypto_des.c` initializes DES with 8 bytes and TDES with 24 bytes, propagates init errors, and calls only init/ecb. `bsd/netinet6/esp_core.c` checks weak keys in 8-byte components and treats every nonzero result as rejection. `bsd/nfs/gss/gss_krb5_mech.c` invokes the void parity helper with exactly 8 bytes; `bsd/nfs/gss/ccrypto.c` forwards it without a result. The helper signatures are the genuine `void *key, unsigned long length` typedefs in `libkern/libkern/crypto/register_crypto.h`.

The selected `roundkey` member has no consumer beyond its declaration in the selected source search. It is NULL and unsupported here; this does not establish general external mode API compatibility. `impl` is the genuine `CC_IMPL_UNKNOWN`, not an invented DES implementation ID. CBC `custom` is NULL because these are direct typed callbacks. Source audit and actual target layouts will be bound in evidence, not inferred from host sizes.

Mbed TLS is pinned to `068ff080b369adfac81509f9b57b2afabaf82dc5`; `vendor/provenance.json`, NOTICE and the unchanged LICENSE retain source/archive/file hashes and Apache-2.0 choice. The genuine DES tables, key schedules, ECB and CBC bodies are unchanged. The only source patch omits an unused assert.h include under the named freestanding profile; library/des.c contains no runtime assert invocation. The minimal profile rejects alternative backends and assembly. There are no SDK record replicas or function-pointer casts.

The single externally defined `mbedtls_platform_zeroize` is a dependency on the already accepted KRN-029 XTS implementation. This adapter only imports it. Qualification links the accepted XTS/AES provider unchanged; it does not introduce another global zeroizer. This dependency must be supplied when integrating later; no provider registration is implied.

## Contracts

Factories admit selectors 0 or 1, preserve output descriptors on invalid selectors, and create four ECB plus four CBC variants. Retain an immutable descriptor for the entire context lifetime. DES accepts exactly 8 bytes. TDES admits selected 24 bytes plus the explicitly additional local 16-byte EDE2 policy (K1,K2,K1). This extra policy is not a claim about Apple's private behavior. Init ignores parity bits and does not automatically reject weak keys: key admission remains a separate caller policy, consistent with the primitive and vector corpus.

Contexts are 16-byte aligned, caller-owned and self-contained schedules. Init copies raw keys and retains no input pointer. Context copies are independent at rest; encrypt/decrypt reads the original context without changing it by copying the typed primitive schedule into bounded local storage. No heap, OS, entropy, mutable key registry or generation counter is involved. Context bytes and descriptor must not be modified during operations. Callers must honor init failure. Failed admissions preserve the prior context and all data/IV. A failed reinit therefore leaves the old key; it must not be used as the rejected new key. Clear with the matching immutable descriptor wipes exactly the advertised context size; callers clear each retained copy at end of lifetime.

Positive operations require real buffers, checked numeric extents, overflow-safe block-to-byte conversion, exact in-place or disjoint input/output and no overlap with context. Partial overlap is rejected. CBC IV uses 16-byte-aligned genuine opaque storage, reads/writes only 8 bytes and must be separate from context and data. Successful CBC updates IV to the last ciphertext block for both directions; split operations continue the chain. Zero blocks require a valid context but permit NULL data/IV and make no writes. Unaligned data bytes are allowed. A context from a different variant or an uninitialized/cleared context is rejected. There is no promise to detect arbitrary schedule byte corruption or to validate whether arbitrary numeric pointers refer to mapped allocations; ownership and allocation sizes are the caller's responsibility.

Admission errors return genuine CCERR_PARAMETER, block-count overflow CCERR_OVERFLOW, invalid lifecycle/variant CCERR_CALL_SEQUENCE. An unexpected primitive failure returns CCERR_INTERNAL; its output must be discarded. The selected regular software primitive cannot fail after admitted block length, but arbitrary backend failure atomicity is not claimed. CBC IV is committed only on success. Temporary raw keys, schedules, IVs and weak-key copies are cleared by the imported zeroizer.

The weak helper admits exactly 8 bytes, classifies the genuine 16 weak/semiweak DES keys while ignoring parity through a normalized local copy, never modifies the input and returns 1 for weak / 0 for strong. Invalid pointer/length returns CCERR_PARAMETER (nonzero, so selected wrappers reject). The void parity helper admits exactly 8 bytes, changes only parity low bits to odd parity and preserves all key bits. NULL/invalid length/numeric-wrap input is a deterministic no-op. No 16/24-byte helper policy or complete private helper equivalence is claimed.
