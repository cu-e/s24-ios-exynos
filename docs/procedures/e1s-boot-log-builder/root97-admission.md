run-root97.py is a thin exact measurement adaptation of the accepted root75/
root83 pattern. It reuses the pinned qemu_host.run/sample, VM022 owned
cancellation and install_work_guard. No new timer, generic executor, compiler
flags, source changes or target execution are introduced. All preparation here
is source AST and hash binding only. The root must independently review the
adapter packet and create its separately hashed, unexpired approval before
invoking it once in a clear exclusive queue window. A proposed grant template
is documentation, not an active grant. External root supervision is 690 seconds;
the existing work guard is 600 seconds including all three sequential stages.

The exact stages are eight source-hook controls (120 seconds), one ordinary
builder (remaining work window, at most 600 seconds, original 120-second child
timeouts), then genuine ELF/Image inspection and twelve negative derivatives
(120 seconds, within remaining whole work window). The 23 builder commands
include the original 21 vectors plus log patch check/apply after RAM/framebuffer.
Source verifier queries and tools' internal subprocesses are additional existing
provenance. At most one compiler invocation runs at a time; RSS supervision
covers controller plus all descendants, capped at 2 GiB. Admission and every
stage require MemAvailable at least 4 GiB and no existing memory pressure.

The adapter checks all frozen inputs before and after work, saves combined raw
logs and child results, records every observed child session, uses finite owned
cleanup, and releases only its own heavy reservation after zero live survivors.
An unexpected exit, stop event, changed binding, resource condition or cleanup
failure stops later stages. All outputs must be new. No retry or resume exists.
The environment is explicit: private HOME/tmp/Zig caches, /usr/bin:/bin PATH,
C locale, no Python user site/bytecode and unchanged frozen Git options.

After a genuine builder success, the adapter independently hashes the actual
report and loader.c.o once and compares their SHA/size to the inspector's
captured bytes. These are observed post-build content bindings; no external
prior authentication or current-path identity is claimed. The inspector binds
ELF/Image SHA/size to the actual report and uses identical bytes for layout and
result hashes. Eight original ELF/Image/boot/tar products are preserved.

The adapter does not record the experiment result, complete STR031, publish to
MAIN, run common checks, launch a guest, operate a phone or qualify native RAM
ownership. Kernel0011/0012 fixed writes, mappings, early physical retrieval,
cache/reset persistence and recovery remain unqualified. The original probe's
physical diagnostics/MMIO assumptions likewise remain unchanged and unqualified.
