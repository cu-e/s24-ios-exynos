# Exact BYH3 vendor RIL input acquisition

CELL-010 uses the existing user request to collect required technical device data and authorized android-readonly scope. It extends passive inventory to five named non-personal vendor shared libraries for CELL-009 offline analysis. No phone write, pairing, adb root, su, privilege/settings change, app installation, reboot, modem command or binary execution is part of acquisition. Native and android-app scopes remain unauthorized.

The collector selects one already-authorized ADB endpoint (or an explicit --device when needed), then requires exact SM-S921B/e1s/S921BXXS9BYH3 properties and uid2000. It does not infer bootloader unlock, root or native recovery from those properties. Target identity is checked again after acquisition.

Only /vendor/lib64/libsec-ril.so, libsec-ril-dsds.so, libsitril.so, libsecril-client.so and libsitril-client.so are candidates. They are possible filenames, not a promise that this firmware uses every one. Only readable regular files from64 bytes through64MiB are copied; symlinks and other paths are not followed. Missing candidates remain unavailable. The narrow list does not establish a whole-phone absence result or justify requesting root.

For each copied library record remote SHA256 before/after, local byte size/SHA256 and ELF64 little-endian AArch64 ET_DYN header identity. A header check is not full ELF, ABI, command-schema or runtime validation. A changed digest/identity or wrong architecture prevents a pass. Matching file provenance does not establish a RIL-to-modem command table, SIM service, data or eSIM operation.

Raw source code/binaries and logs remain inside a fresh ignored artifacts/ril-capture run. Run directories are0700; files are0600. Device enumeration serials are not saved, and selected-device values are redacted from command records/logs. No identifiers, personal files, radio traces, process descriptors, calibration/NV, subscription data, modem devices or partitions are read. Version only sanitized file metadata/digests and evidence; never the proprietary libraries.

Individual ADB commands have a45-second maximum within a240-second total command budget. Loss of connectivity retains the observed failure; it does not trigger reconnect, pairing, settings changes or reboot. Stopping a passive host copy does not require a phone recovery mechanism. The collector never opens the modem device or sends an inferred RIL request.

Review the [official ADB command documentation](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md) for pull/shell semantics. Command text uses a literal remote allowlist and no user-controlled remote shell interpolation. Eight synthetic host guard groups cover wrong/ambiguous identity, file boundaries, digest/build changes, architecture, endpoint privacy, reference-tag selection, independent sync-read agreement and forbidden-operation rejection. Those tests do not count as device evidence.
