Lifecycle and admission:

- AES keys 16/24/32 bytes. Ordinary init leaves WAIT_IV; nonzero IV then AAD updates, text updates, finalize. Reset retains key and returns WAIT_IV. Message text is bounded by genuine `CCGCM_TEXT_MAX_NBYTES = 2^36-32`; AAD and IV length encodings are bounded by `UINT64_MAX/8`. Positive text moves to DATA and later AAD is rejected, including zero-length AAD. Zero text in AAD is a no-op. Finalization consumes the message, including an authentication mismatch.
- Explicit selected tag lengths 4..16 are supported; other lengths are rejected. This is a bounded backend policy, not a claim that every unspecified length of every Apple implementation is supported. Actual ESP uses 16; primary NIST and independent tests cover the selected truncations.
- Inputs/outputs must be accessible for admitted extents, disjoint from context; text input/output may be disjoint or exactly in-place. Partial overlap, null nonempty buffers, wrapping extents, wrong mode/helper family, wrong phase, limit overflow and invalid tags are rejected before changing context or caller output. Tests preserve snapshots to check this. Unexpected internal backend failure is distinct: current update output is wiped and context cleared rather than treated as ordinary admission rejection.
- Genuine selected [gcm_update](https://github.com/Mbed-TLS/mbedtls/blob/068ff080b369adfac81509f9b57b2afabaf82dc5/library/gcm.c#L564) emits exactly the input byte count immediately; [gcm_finish](https://github.com/Mbed-TLS/mbedtls/blob/068ff080b369adfac81509f9b57b2afabaf82dc5/library/gcm.c#L650) emits no pending text. Tests compare output before finalization at arbitrary byte splits, including partial AES blocks. Keys/IV/AAD are not borrowed after return; local key/state/tag temporaries are wiped through the single accepted zeroizer.
- On decryption, finalize uses genuine constant-time `mbedtls_ct_memcmp`, returns `CCERR_INTEGRITY` on mismatch, and overwrites caller tag with the computed tag on both match and mismatch, as the selected header requires. Every streamed plaintext byte remains **provisional until finalization returns success**. The API cannot retroactively erase buffers the caller has already consumed or discarded. Constant-time tag comparison does not establish end-to-end side-channel safety for the table-based software AES profile.

Managed nonces:

- The initial exact 12-byte IV is consumed by init_with_iv. Its first 4 bytes are an immutable salt; its final 8 bytes form an unsigned big-endian counter. Reset discards only message state. inc_iv requires managed WAIT_IV, validates output/mode first, increments the counter transactionally and starts a fresh message. Counter wrap returns `CCERR_OVERFLOW`, with unchanged context/output. Repeated reset does not roll back, release, or replenish nonce authority. Reset-before-finalize reserves/discards that nonce, matching real consumers that reset before incrementing.
- Ordinary init cannot use inc_iv; managed init cannot use explicit set_iv. Reinitializing a live managed context is rejected, even after reset/finalization/exhaustion. Explicit clear/destruction permits reconstruction; the caller must then enforce uniqueness. The adapter cannot maintain persistent/global uniqueness across process restart, memory reconstruction, another same-key context, or independent devices. Ordinary explicit-IV uniqueness is entirely the caller's responsibility. It is not a persistent nonce manager, key store, or proof of protocol security.
