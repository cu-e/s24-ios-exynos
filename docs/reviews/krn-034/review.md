## State, errors and authentication boundary

The owned state machine requires initialization, one explicit nonce, AAD before text, one text direction, then finalization or verification. Reset reconstructs the original key, resets primitive/MAC state and lengths, and requires another explicit nonce. Nonce uniqueness is the caller's responsibility: resetting and supplying a repeated nonce is not prevented by a global nonce registry. Existing nonce bytes can remain in the reset owned structure until the next setter; they are not used without that setter.

Input/output numeric extents and context alignment are checked before access. Nonempty null or wrapping extents, context aliases and partial overlap are rejected. Exact input/output identity is supported. Accessible mapped storage, correct capacities, exclusive serialization and integrity of the caller-owned context remain preconditions; numeric extent checks cannot validate mappings. Invalid operations preserve the original context and output because work is performed on a local state copy before a successful store. A bad authentication tag intentionally consumes final state instead of permitting retries.

The glue derives the one-time Poly1305 key from counter zero, then starts payload processing at counter one. It pads AAD and ciphertext to 16-byte boundaries and appends their little-endian 64-bit byte lengths, matching the explicit-nonce AEAD construction in [RFC 8439](https://www.rfc-editor.org/rfc/rfc8439.html). AAD count overflow, the selected `(2^38)-64` text limit and the actual primitive counter-exhaustion guard are checked before output changes. Injected arithmetic states test guards; they do not constitute a 256 GiB message execution.

Decryption authenticates ciphertext before overwriting an in-place buffer, but emits provisional plaintext before tag verification. Callers must quarantine it and discard it after a failed verify. The API is not a release-only-after-authentication interface. All 16 tag bytes participate in the source loop; retained actual ARM assembly review describes its public-index loop. This is not a whole-program constant-time or side-channel qualification. Explicit context clear and primitive/temporary wiping are reviewed; actual clearing of selected context bytes is testable, whereas copies in registers, caller memory, crash dumps and the complete machine are outside this evidence.
