P2 finding: state the initializer lifetime boundary explicitly. `pcm_host.c:71-74` unconditionally assigns a zero host, including leased bits, epoch, issued serial and stop serial. `pcm_host.h:42` declares init without any fresh-storage/quiescence precondition. The ownership section in `docs/procedures/audio-host/README.md:64-83` promises a new epoch, unique local leases and retirement/fence before reuse, but does not bound those promises to an uninterrupted initialized host lifetime or forbid init as reset. Conventional fresh-only initializer intent would resolve this; it should be explicit before a future backend integrates these safety-relevant premises.

The independent [harness](harness.c)'s final block reproduces the ambiguity using public APIs only:

1. init; bind plan with epoch 1; start; claim slot 0 → old lease `(epoch 1, serial 1, slot 0, offset 0, period_bytes)` remains outstanding.
2. init again without Stop, CLOSED, lease retirement or provider fence → state becomes IDLE with no leased bits.
3. bind the same plan with epoch 1; start; claim slot 0 → the new lease has identical fields.
4. retire the **old** lease → returns PCM_OK and clears the new reservation.

Recommended narrow correction: document init as fresh/unexposed storage only, or reuse only after the previous mapping and all holders/callbacks are fully retired/drained; it is not a live reset/recovery/cancellation API. Explain that reconstruction resets local counters and requires fresh provider identity/epoch association beyond this object. If live reset is intended, provide a separate checked transition. Do not make an initializer inspect uninitialized storage. No production change was made by this review. Under a fresh-only lifetime premise, this counterexample is outside the supported contract; ordinary state transitions below did not show a bypass. Severity is P2 for the missing explicit contract, not a claim that valid captured DSP bytes can call init or control host state.
