The parser's exact-length check precedes every input read (`protocol.c:15-21`); 12-bit coordinate extraction, zero-based IDs 0..9, split touch-type bits and five-bit remaining count agree with the pinned Samsung declaration (`protocol.c:35-45`). Inclusive maxima are validated before mapping. Unsupported coordinate types and invalid transitions trigger resynchronization. Lower-priority bytes include source-defined sensor metadata; they do not authenticate transfers. Samsung status declarations/handling confirm the status subtype mask and ready/reset condition (`protocol.c:23-33`). Treating every error-subtype status as loss is documented conservative project policy.

The adapter publishes one record's UI event per accepted callback; it does not claim atomic multi-contact frames or infer FIFO integrity from `remaining` or the source's end-of-movement field. The backend must assemble complete 16-byte records and report transport loss. `protocol.c:143` returns busy before parsing when delivery is pending: the backend must retain that input or report loss, as documented. The code cannot detect a packet the caller silently discards.

Candidate state commits only after callback acceptance (`protocol.c:70-84`). Declined delivery retains its event and blocks new feeds. Cancellation may replace an unpublished event using the last acknowledged sequence and time; it cannot undo pending Stop (`protocol.c:111-127`). Callback reentry through feed/retry/resync/Stop returns busy. Fresh initialization requires cancellation before contacts; reinitialization of live storage and callback mutation are explicitly outside the API contract. Time checks use the last acknowledged event, allowing replacement cancellation to precede an unpublished event's timestamp. The final uint32 sequence remains available for acknowledged cancellation; exhaustion does not wrap (`protocol.c:90-105`). The stopped flag describes logical acceptance and does not assert hardware quiescence.

The serializer copies its input before writing, checks the exact 40-byte output extent and reuses the UI decoder for field validity (`protocol.c:160-177`). Shared normalization uses a uint64 product and bounded maxima. These checks do not establish Apple HID ABI compatibility.
