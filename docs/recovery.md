# Восстановление и границы автономности

**Статус: не подготовлено и не испытано на аппарате владельца.** Этот документ — шаблон исследования; он не инструкция к прошивке.

| Условие | Текущее состояние |
|---|---|
| Точная модель/firmware/bootloader | Не измерены |
| Исходные образы именно этой прошивки | Не получены |
| Backup с размером/хэшем/местом вне Git | Не получен |
| Вход в recovery/Download Mode | Не проверен |
| Host-инструмент восстановления и права USB | Не проверены |
| Проверенное восстановление Android | Отсутствует |
| Управляющий канал из XNU | Отсутствует |
| One-shot boot / аппаратный watchdog | Не реализованы и не проверены |

Сохранность разделов Android, доступность его загрузки и сохранность данных — отдельные свойства. Backup не доказывает способность восстановления. Структурно правильный BOOT не доказывает исполнение. Read-only UFS не устраняет риск зависания оборудования.

Первый native-сеанс требует конкретного разрешения владельца, точного scope, исходного состояния, образа с хэшем, процедуры возврата, доступности пользователя и критериев остановки. Всё это оформляется в карточке NAT-003. Обычные host-задачи этого не требуют.

Автоматический цикл запрещён до проверенного возврата. После потери связи нельзя бесконечно повторять прошивку/перезагрузку. Остановить работу агента не значит отменить аппаратные действия.

Для длительных автономных native-экспериментов понадобится независимое управление/восстановление, а возможно отдельный тестовый аппарат. Наличие такой возможности на основном S24 пока не установлено.
