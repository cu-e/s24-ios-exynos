HackiOS review for Samsung Galaxy S24 / Exynos 2400
Date: 2026-11-05

English translation of the historical source review. Findings describe the original review, not a new upstream check or device test.

Main finding: https://github.com/RNDMBG/iOS-On-S24
Exact device: SM-S921B, e1s, S5E9945 / Exynos 2400.
Reviewed commit: c8860decc62c6d6180e609036d027a2997972420 (2026-11-03).
The repository dates from 2026-10-22. Its target at review time was iOS 16.5 / xnu-8796.121.2, although the GitHub description still said 16.7.

The published early implementation includes a loader, E1S XNU configuration, STM SPI9 touch patches, read-only UFS 4.0/MCQ, PMIC/RTC/battery code, and display/camera diagnostics. Its documentation explicitly states that no image has been flashed or booted on a phone. Hardware execution of XNU, launchd, SpringBoard, touch and UFS is unconfirmed.

According to the 2026-11-03 log, the kernel links but the build stops at the final check_all_exports step. CI checks host tests and patch application; it does not build the kernel. GitHub releases were empty and the tree contained no .img/.tar files. Hashes in the documentation refer to the author's local builds.

All documented boot-screen images/MP4s are host-rendered or QEMU simulations; these previews do not execute XNU. The test /sbin/launchd is a custom static Mach-O, not Apple's launchd. docs/e1s-userland.md explains this explicitly.

The port has no Xclipse 940 GPU implementation; the initial target is CPU rendering. Native Wi-Fi/BT/modem/audio are also missing. All 10 cores are described in configuration and a separate SMP image; default cpus=1, with no hardware verification.

Related implementations:
- S21+ / Exynos 2100: https://www.reddit.com/r/hackios/comments/1xldki1/ claims a home screen, touch and 8 cores. No code was available in the reviewed post/comments; reproducibility is unestablished.
- S20+ / Exynos 990: https://github.com/stormtroopxyz/y2sios is a detailed published port. The author documents UI, Mali-G77/Metal, Wi-Fi, UFS, 8 cores and thermal/governor support. Audio/modem/camera do not work. These claims were not independently tested on a device.
- S9 / Exynos 9810: https://github.com/Scion-Project/hakios-starlte and the shared Scion-Project/hackios-xnu-kernel document touch, CPU and Mali/Panfrost. Several other drivers are authored but unconfirmed.
- S7 / Exynos 8890: https://github.com/wardevsa/ios-a5xelte/tree/herolte uses EAGL/OpenGL ES/Panfrost without Metal; the author reports 35–38 fps and many nonworking subsystems.
- S10+ / Exynos 9820: https://github.com/orhunnx/beyond2lte-ios has experimental userspace boot and 8 cores, incomplete UI and no GPU.

An S24-specific component: https://github.com/JimVulkan/radv-xclipse provides Mesa RADV Vulkan on Android for Xclipse. Release notes identify Xclipse 940 testing on SM-S921B/SM-S926B. This is not an XNU driver. Combining metal2vulkan, RADV and a future XNU adaptation of the low-level SGPU driver is an engineering possibility, not a published working iOS port.

Boot environment: the iOS-On-S24 author documents Android 15 / S921BXXS9BYH1, bootloader bit 9, TWRP and Magisk. This does not establish that S24 devices on newer One UI can be unlocked. Mu-Silicium lists e1s as Inactive, BIT-9, display yes, internal storage/USB/Windows/Linux boot no. Official TWRP support for e1s exists.

Coverage: titles and available self-text from 324 archived r/hackios posts (2026-10-18..2026-11-04) were reviewed; 2478 archived comments were searched and relevant threads read. Primary repositories and selected source files were reviewed separately. The archive may omit posts, edits and recent comments. Videos were not independently verified as hardware execution. Nothing was flashed and no port code was executed.

The imported archive provides posts-index.csv, research-manifest.json and copies of key S24-port documentation. These remain historical local research material, not observations of the owner's phone.
